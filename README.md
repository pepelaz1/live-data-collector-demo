# Прототип устойчивого сборщика данных

Небольшой пример на Node.js для потокового сбора данных. Локальный имитатор воспроизводит Socket.IO-подобные сообщения, разрыв соединения и ответ `429 Too many requests`. Сборщик переподключается, выдерживает паузу при ограничении запросов и пишет по одной JSON-строке на событие в `stdout`. Диагностика идёт в `stderr`.

## Запуск

Нужен Node.js 22 или новее. Зависимости устанавливать не требуется. В двух терминалах:

```powershell
npm run mock
npm start
```

Проверка: `npm test`.

Пример выходной строки:

```json
{"received_at":"2026-11-08T00:00:00.000Z","event":{"id":"match-1","score":"0:0"},"detail":{"status":"ok","data":{"id":"match-1","price":2.14,"available":true}}}
```

Переменные `SOURCE_WS_URL`, `DETAIL_BASE_URL`, `REQUEST_GAP_MS` меняют адрес источника, адрес деталей и минимальную паузу между запросами. Формат события `live_update` и адрес деталей в реальном проекте нужно настроить по предоставленному коду и документации источника.

## Границы примера

Имитатор не обращается к стороннему сайту и не содержит учётных записей, прокси или обхода ограничений. Он показывает обработку типовых сбоев, но **не подтверждает** требуемую заказчиком частоту обновления, срок жизни сессии пять дней или непрерывную работу неделями на реальном источнике. Для такой проверки нужны разрешённый доступ, исходники текущего парсера и длительный прогон с измерением ошибок и пропусков.
